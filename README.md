# 银龄安心查 Android MVP 0.3.4

面向老年消费场景的 Android 原生风险初筛与官方核验辅助 App。

## 0.3.4 官方查询截图辅助核对

- 用户打开官方查询入口并完成查询后，可以选择查询结果截图继续核对。
- 复用 ML Kit 中文 OCR，在手机本地识别截图，不上传图片或识别文字。
- 自动辅助比较注册 / 备案号、产品名称、注册人 / 备案人、型号规格和登记状态。
- 对登记用途、适用范围和部分文字给出“需要人工确认”，避免把关键词命中当成官方结论。
- 统一使用“截图文字一致、可能不一致、未识别、需要人工确认”四种谨慎状态。
- OCR 辅助结果与人工记录明确分开；用户在人工核对区作出的确认可以消除对应的截图提醒。
- 综合摘要、购买建议和分享报告同步携带截图辅助核对结果与识别时间。
- 本版仍未自动查询官方数据库，截图 OCR 结果不代表商品真假、官方认证或行政认定。

## 0.3.3 官方人工核验与证据记录

- 将官方来源区分为“主要核验入口”和“辅助核对入口”，并为每个入口提供自然语言查询指引。
- 点击官方入口时自动复制已识别的注册 / 备案编号，减少老年用户切换页面后的输入负担。
- 按商品登记类型生成逐项核验清单，覆盖编号、产品名称、注册人 / 备案人、型号规格、登记用途和登记状态。
- 用户可如实记录“找到记录、暂时没找到、页面异常”以及各字段一致 / 不一致，结果页同步给出谨慎建议。
- 分享报告携带人工核验来源、打开时间、记录时间和逐项结果，便于家人继续复核。
- 人工记录仅保存在当前分析页面，不写入历史数据库；退出或重新分析后不会保留。
- 本版仍未自动连接官方数据库，不会把打开网页或人工勾选显示成“官方认证”或“自动核验通过”。

## 0.3.2 淘宝 / 天猫商品详情自动解析 MVP

- 在严格 HTTPS Host 白名单内解析淘宝、天猫直达链接、最多 5 次普通 HTTP 重定向，以及短链公开 HTML 中明确出现的官方商品地址。
- 仅尝试读取无需登录即可公开访问的 HTML，优先解析 JSON-LD、Open Graph、Meta 和页面标题。
- 商品名称、页面显示价格、卖家、品牌、型号、规格、描述和少量主图都记录字段来源与置信度。
- 页面标题和描述可以补充 ProductInfo 并参与原有风险分析；包装 OCR 字段优先，店铺不会被当作生产企业。
- 遇到登录、验证码、403、未知跳转、超时或解析失败时正常降级，可打开商品页或选择截图继续 OCR。
- 请求不携带淘宝账号、Cookie 或登录 token，不执行 JavaScript，不调用私有接口，不绕过平台限制。

## 0.3.1 主流电商商品链接识别 MVP

- 可从纯链接或整段分享文案中自动识别淘宝、天猫、拼多多、京东和抖音官方域名。
- 对常见商品链接可靠提取商品 ID，并对平台短链接如实标记“需要进一步解析”。
- 清理 `spm`、`utm_*` 等明确的追踪参数，同时保留商品定位所需参数。
- 严格按 URL Host 判断平台，`fake-taobao.com` 等相似域名不会被误认为淘宝。
- 链接会在风险分析前从文字中移除，分享文案中的宣传内容仍可正常参与风险规则分析。
- 首页、结果页和分享报告新增老人友好的“商品来源”说明。
- 本版不跳转解析短链、不抓取商品页面、不使用登录态，也不伪造标题、价格、店铺或商品详情。

## 0.3.0 官方信息核验 MVP

- 识别医疗器械、药品、保健食品和化妆品的常见注册 / 备案编号格式。
- 根据结构化商品信息判断当前是否具备官方核验条件，并说明缺失字段。
- 按编号类型匹配国家药监局、医疗器械 UDI、市场监管总局和特殊食品信息查询平台等官方入口。
- 统一展示核验状态、官方数据来源和核验时间；本版核验时间始终如实显示“尚未查询”。
- 增加宣传内容与商品登记类型的第一层冲突提示，不直接作出违法、假货或官方认证结论。
- 结果摘要同时展示宣传风险、商品信息完整度和官方核验状态。
- 分享报告升级为商品信息、风险分析、官方核验和购买建议四个部分。
- 将核验业务逻辑与 Compose UI 拆分，并增加可重复运行的单元测试。

## 0.2.2 商品信息结构化提取

- 从 OCR 或手动输入中整理商品名称、品牌、生产企业、型号、规格/净含量、注册/备案号和价格。
- 结果页逐项展示已识别内容和缺失字段，不再只显示型号与价格。
- 对商品名称提供谨慎的无标签推测，其余关键字段优先依据包装标签提取。
- 提醒用户补拍包装正反面，并明确所有提取内容都需要对照原包装核实。
- 分享给家人的风险报告会同时带上已整理的商品信息。

## 0.2.1 交互优化

- 页面避开状态栏、摄像头区域和底部导航栏。
- 键盘弹出时页面仍可滚动到“开始分析”，分析后自动收起键盘。
- 使用“拍商品查”“选截图查”等更直接的老人友好文案。
- 结果页直接解释“为什么风险高”。
- 官方记录区域明确显示“尚未自动核验”。
- 结果页底部常驻“发给家人一起看看”按钮。

## 这一版和网页 0.1 的区别

- 原生 Android App，不是 WebView。
- Kotlin + Jetpack Compose。
- 直接调用系统相机拍照识别。
- 从系统相册选截图。
- 使用 Google ML Kit 中文 OCR，本地识别商品截图文字。
- 不需要申请相册存储权限。
- 健康、节电、赚钱三类高风险消费话术初筛。
- 自动提取商品名称、品牌、生产企业、型号、规格、注册 / 备案号和价格。
- 风险分 + 可解释命中原因。
- 按商品类别给出国家药监局、市场监管总局、全国标准信息平台等官方核验入口。
- Android 系统分享，可直接发给微信/短信等家人协同核验。
- 明确区分“风险初筛”和“官方认定”。

## 当前边界

### 已经真实完成
截图 / 分享文案 → OCR / 链接识别 → 结构化提取 → 风险识别 → 编号分类 → 核验准备度 → 官方人工查询入口 → 查询结果截图辅助比对 → 逐项人工核对记录 → 宣传冲突提示 → 分享

### 还没有伪装完成
保证所有淘宝 / 天猫页面都能完整读取、读取动态详情或评论、自动查询国家数据库。

也就是说，本版本不会显示假的：
- “国家认证：通过”
- “该品牌可以买”
- “未备案，所以一定是假货”

如果未来存在稳定、合法且适合 App 调用的官方公开接口，可以继续升级为：

```text
截图
 ↓
OCR
 ↓
品牌 / 产品名 / 型号 / 注册编号结构化抽取
 ↓
官方公开接口或合规数据集
 ├─ 国家药监局
 ├─ 医疗器械 UDI
 ├─ 市场监管总局
 └─ 国家标准
 ↓
精确匹配 + 数据来源 + 查询时间
```

## Android Studio 运行

推荐：
- 最新稳定 Android Studio
- JDK 17
- Android SDK 37

步骤（Windows）：
1. 解压项目。
2. 在项目目录打开 PowerShell，执行：
   `powershell -ExecutionPolicy Bypass -File .\bootstrap-wrapper.ps1`
3. Android Studio → Open → 选择本项目文件夹。
4. 等待 Gradle Sync。
5. 准备 Android 6.0（API 23）以上真机或模拟器。
6. Run `app`。

`bootstrap-wrapper.ps1` 只下载 Gradle 官方的 `gradle-wrapper.jar`。之所以单独放这个步骤，是因为当前生成环境不能直接把外部二进制 JAR 打进交付包；项目源码本身已经完整。

首次 Gradle Sync 需要联网下载依赖。

## 隐私设计

0.3.4 的商品截图 OCR、官方查询截图 OCR、链接识别、结构化提取、编号分类、风险分析和人工核验记录仍在设备本地完成。
App 仅在用户点击分析后请求当前淘宝 / 天猫链接的公开页面，不保存 Cookie、登录 token、淘宝账号或浏览历史。
点击官方查询按钮或“打开商品页面”时，会交给系统浏览器或对应平台 App。
人工核验记录只存在于当前页面内存中，重新分析或关闭 App 后不会保留。
