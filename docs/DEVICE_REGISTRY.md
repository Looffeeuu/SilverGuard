# 医疗器械登记数据离线核对

识别到医疗器械注册证或备案编号后，App 可以在本机的登记数据里查这个编号，并把登记的产品名称、注册人 / 备案人与包装上的信息对比。它能发现一种常见手法：**包装上印的是真实编号，但这个编号属于别的产品或企业**。

## 当前状态

代码已经完成，但 **App 里还没有内置任何真实数据**，所以这个功能目前不会出现在界面上。

国家药监局医疗器械唯一标识数据库（UDID）的下载页说明数据“供公众、医疗器械生产经营企业和医疗机构等各方查询使用”，页脚标注“版权所有：国家药品监督管理局”。我们没有找到明确允许重新打包、随 App 分发的条款。确认可以使用之前，不把数据放进仓库或安装包。

确认后可以选择：

| 方式 | 说明 |
| --- | --- |
| 内置到 APK | 放到 `app/src/main/assets/udi-index/`；离线可用，安装包预计增加 10–20 MB，数据随 App 版本更新 |
| 按需下载 | App 首次核对器械时下载到 `filesDir/udi-index/`；安装包不变，可单独更新。读取代码已支持，下载流程尚未实现 |

两处都有索引时，优先使用下载的版本。

## 数据来源

- 下载页：<https://udi.nmpa.gov.cn/download.html>
- 全量包约 316 MB（2026-10-01：629 万条产品标识），另有每月、每周、每日增量包
- 每个 `<device>` 记录中使用的字段：

| 字段 | 含义 |
| --- | --- |
| `zczbhhzbapzbh` | 注册证编号或备案凭证编号，一条记录里可能有多个，用逗号分隔 |
| `ylqxzcrbarmc` | 注册人 / 备案人名称 |
| `cpmctymc` | 产品名称 |
| `qxlb` | 器械类别（器械 / 体外诊断试剂） |
| `versionStauts` | 新增 / 更新（删除按防御性处理） |

**数据包中还有企业联系人的电话和邮箱，生成索引时完全不读取这些字段**，测试会检查输出中不包含它们。

## 生成索引

```powershell
python tools\udi_index\build_udi_index.py --out udi-index UDID_FULL_RELEASE_20261001.zip UDID_MONTH_UPDATE_202610.zip
```

先放全量包，再按日期顺序放增量包。脚本只用 Python 标准库，按流读取 XML，不需要把全量包整个读入内存。输出：

- `manifest.json`：格式版本、数据日期、记录数和来源文件
- `shard-00.tsv.gz` 到 `shard-63.tsv.gz`：每行是匹配键、编号、注册人 / 备案人、最多 3 个产品名称、类别

匹配键的规则是 NFKC 规范化、转大写、去掉空白和标点、去掉末尾的“号”；分片编号是匹配键 UTF-8 的 CRC32 对 64 取余。Python 和 Kotlin 两边的测试固定了同一组数值，任何一边改了算法都会失败。

## 在模拟器上试用

只用于本地开发，不要提交生成的索引：

```powershell
adb push udi-index /data/local/tmp/
adb shell run-as com.silverguard.app mkdir -p files/udi-index
adb shell run-as com.silverguard.app cp -r /data/local/tmp/udi-index/. files/udi-index/
```

不再需要时，在系统设置里清除 App 数据，或在 Android Studio 的 Device Explorer 中删除 `files/udi-index`。

然后完全关闭 App 再打开（索引在 ViewModel 创建时载入）。

## 结果怎么展示

- **找到且一致**：在“显示详细信息”里列出登记的产品、企业和类别，并提醒“编号存在不代表宣传的功效已经获批”。
- **找到但不一致**：直接显示在结果页上，并且：
  - 标题改为“信息对不上，建议暂缓付款”，“官方核验”一栏显示“编号登记信息不一致”；
  - 朗读和分享报告都提示可能借用了他人的注册证；
  - 显示求助卡片。
  - 风险分数**不变**，因为它只衡量宣传用语。
- **没找到**：说明唯一标识数据库没有覆盖全部医疗器械、数据有更新延迟，**没找到不等于假货**，以官方注册证查询为准。
- 每次都会写明数据截至日期，并说明不是实时查询。

## 已知限制

- UDI 是分批实施的，不是所有已注册的医疗器械都在数据库里。
- 本地数据会过时，新批准的注册证要等下次更新索引后才能查到。
- 同一编号以最新数据包中的注册人为准，最多保留 3 个产品名称。
- 名称比对使用包含关系和字符重合度，OCR 错字或品牌简称可能导致误判“不一致”，所以界面只提示“对不上，请到官方入口再核对”，不下真假结论。
- 实际数据包中只见到“新增”“更新”两种状态；“删除”“注销”是按防御性处理的，尚未在真实数据中验证。
